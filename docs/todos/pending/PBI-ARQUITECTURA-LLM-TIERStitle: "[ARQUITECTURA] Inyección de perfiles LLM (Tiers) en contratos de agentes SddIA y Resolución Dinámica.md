Contexto ArquitectónicoLa selección manual de modelos LLM (Model Multiplexing) según la fase de trabajo genera una grave fricción termodinámica y rompe la automatización de la línea de montaje. Para consolidar la "Física del Valor" en la Librería SddIA, el ecosistema debe auto-enrutar la carga cognitiva: asignar modelos de alto coste (Tier 1) a tareas de abstracción y arquitectura, y modelos económicos (Tier 3) a tareas de forja mecánica.Para preservar el principio de Ceguera Espacial, el genoma de los agentes jamás debe conocer el nombre comercial de un LLM. El agente solo exige un nivel cognitivo abstracto, el cual es resuelto físicamente por el entorno local en tiempo de ejecución.2. Especificación BásicaModificación del Genoma (Core): Actualizar el contrato base de los agentes (agents-contract.md) para exigir la declaración obligatoria del bloque llm_profile dentro de la configuración de cada JSON de agente.  tier: high (Arquitecto Dédalo / Mayeuta) -> Operaciones de especificación, diseño y clarificación.  tier: medium (Argos) -> Planificación, validación estructural y auditoría de artefactos.  tier: low (Tekton) -> Ejecución iterativa, escritura pura de código y tareas mecánicas.  Matriz de Resolución Local (Instancia): Mapeo de los requerimientos abstractos a modelos físicos inyectando variables directamente en la Jerarquía de Bóvedas del proyecto (.SddIA/.dev/.env), garantizando la separación estricta entre código rastreado y memoria volátil local.  Propagación del Payload: El orquestador de procesos (execute-process) extraerá este perfil del JSON del agente y lo anexará al payload de salida.  3. Clarificación (Filtro Antientrópico)Soberanía de Entorno (Desacoplamiento): El mapeo físico no reside en SddIA/. Se utilizan variables de entorno en la instancia local para definir el proveedor:SDDIA_LLM_TIER_HIGH="claude-3-opus-20240229"SDDIA_LLM_TIER_MEDIUM="deepseek-r1"SDDIA_LLM_TIER_LOW="ollama/llama-3.2"De esta forma, la Librería es agnóstica; si se ejecuta en una máquina Linux Mint que sirve modelos localmente mediante Ollama y Open WebUI, el entorno se adapta modificando solo su .env sin romper los agentes.Traductor Inerte: El script puente (.SddIA/client/sddia-client-bridge.py) intercepta el payload del CLI canónico, lee la petición de tier, cruza el dato con la bóveda .dev/.env, y formatea la invocación HTTP redirigiéndola automáticamente al motor LLM exacto.  4. Plan de Implementación (Línea de Montaje Táctica)Fase A (Genoma): Actualizar agents-contract.md y los manifiestos JSON individuales de Cúmulo, Cerbero, Tekton, Mayeuta, Dédalo y Argos para inyectar el nodo llm_profile correspondiente.  Fase B (Aduana Universal): Modificar la lógica de carga en execute-process.py (o su equivalente nativo en Rust) para que exponga el llm_profile en el JSON stdout que consumirá el exterior.  Fase C (Bóveda y Puente):Documentar en el .SddIA/.dev/.env.example las nuevas variables SDDIA_LLM_TIER_*.  Adaptar la lógica del backend ligero en Python (sddia-client-bridge.py) para que lea estas variables y enrute el prompt a la API correcta basándose en el tier solicitado.
