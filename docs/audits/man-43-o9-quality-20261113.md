# MAN-43 O9 — calidad y gate de warnings

## Dictamen

El **gate canónico** (`rust-warning-gate` v1.0.0 §2: `rustc` con `RUSTFLAGS=-Dwarnings`) está **verde** en todo el workspace. AC-12 se satisface por esa vía.

Clippy **no forma parte del gate**: §1 de la norma lo excluye explícitamente y `.github/workflows/sddia-index-qa.yml` no lo invoca. No obstante, O9 lo usó como lupa y pasó de un workspace **inmedible** a un residual acotado.

El feature MAN-43 sigue **`NO_APTO_TOTAL`**: C-2 (nombre del schema) y la deuda de genoma permanecen.

## Evidencia

| Comprobación | Resultado |
|--------------|-----------|
| `cargo check --workspace` | Sin errores ni warnings de `rustc` |
| `cargo test -p execute-process --lib` | 816 passed, 1 ignored |
| `cargo clippy --workspace --all-targets` (antes) | `sddia-io` abortaba: workspace no medible |
| `cargo clippy --workspace --all-targets` (después) | Residual solo en `execute-process` (~85 diagnósticos) |
| `rg "clippy" .github/` | Sin coincidencias: CI no ejecuta clippy |

## Hallazgo C-2 (sigue abierto, latente)

El motor compone el schema como `{contract}.schema.json`:

- `capability_di_resolver.rs:354`
- `capability_di_gate.rs:373`
- `capability_di_output_validator.rs:58`

Con `contract: eda.event_manager` resulta `eda.event_manager.schema.json`. En disco solo existe **`eda.event_manager.v1.schema.json`**, y es el único schema del directorio con sufijo de versión. Ningún proceso declara hoy `requires_capability: contract: eda.event_manager`, por lo que el fallo no se dispara; si se declarara, el gate abortaría con `schema ausente`.

**No se corrigió**: `SddIA/library/norms/` es genoma protegido (DA-2) y no existe creator que materialice `*.schema.json` (`norm-creator` escribe `{name}.md`). Dos vías posibles, cada una con su corte:

1. Renombrar el fichero a `eda.event_manager.schema.json`.
2. Enseñar al resolvedor a leer `contract_schema` de `capability-bindings.md`.
