# MAN-43 O14c — Rutas virtuales residuales → `EventUri`, oráculo workspace y dossier AC-13

## Contexto

El test `sddia-daemon-runtime::linear_bridge_webhook::tests::ac13_valid_signature_emits_webhook_source` fallaba de forma determinista (`NotFound`) porque `materialize_pending` grababa en Redb y devolvía un `PathBuf(".events/pending/{id}.json")` inexistente. El mismo patrón existía en `github_bridge::materialize_to_bus`, `route_domain_core::materialize_pending_domain_event`, `kalma2-bridge::eda_productive::domain_event` y 7 claves JSON `"event_path"`.

## Cambio ejecutado

1. **Oráculo G-2 (`eda_event_token_hygiene.rs`):** Ampliado para vetar constructores de `.events/{pending|domain|processing|processed|telemetry|dead-letter}/` y claves JSON `"event_path"` en todo el workspace Rust (con `VIRTUAL_PATH_ALLOW` y `SCAN_EXCLUDE` documentados). Registrado en rojo (5/2) y verificado en verde (7/7).
2. **Daemon y motor (G-1):** `linear_bridge::{materialize_pending, assimilate_*}`, `linear_bridge_webhook::process_signed_webhook` y `github_bridge::materialize_to_bus` pasan a `EventUri`; `route_domain_core::materialize_pending_domain_event` devuelve `EventUri::as_canonical()`; `fractal_bus::stamp_fractal_delivery_state_by_id` desacopla `memory_evolution_ingest_core`; `kalma2-bridge` retira el `PathBuf` virtual; 7 salidas CLI pasan de `"event_path"` a `"event_uri"`.
3. **Genoma (`entity-manager`):** `audit-telemetry-compliance-breach.md` actualizado a `2.0.0` (`breach_event_uri`).
4. **Cobertura y dossier:** `SddIA/core/eda-coverage.json` regenerado con `audit-eda-coverage --scan`; dossier `docs/audits/man-43-o14c-reaudit-ac13-20261116.md` con veredicto propuesto `NO_APTO_TOTAL` (3 fallos fuera de B + residual § 4 para O14d).
